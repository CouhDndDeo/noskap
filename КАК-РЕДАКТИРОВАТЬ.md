# Как добавлять локации и править описания

Весь контент карты лежит в одном файле:

```
packages/web/src/web/data/locations.ts
```

Больше нигде ничего менять не нужно — ни базы, ни админки. Открыл файл,
поправил текст, сохранил, обновил страницу.

---

## 1. Быстрый путь: добавить локацию через пипетку

Самое муторное — узнать координаты точки на карте. Для этого в карту встроена
пипетка, она доступна только в режиме мастера.

1. Открой карту с `?gm=1` в конце адреса.
2. Внизу нажми кнопку **«координаты»**.
3. Кликни по карте там, где должна стоять новая локация.
4. Сверху появится панель: там уже показаны `x` и `y`.
5. Впиши название, выбери тип из списка — и нажми **«скопировать блок»**.
6. Вставь скопированное в конец массива `locations` в файле
   `locations.ts` (перед закрывающей строкой `];`).
7. Замени текст-рыбу на свой лор.

Выйти из режима пипетки — кнопка «закрыть» или клавиша Escape.

## 2. Из чего состоит локация

```ts
  {
    id: "seryy-brod",              // латиницей, без пробелов, уникальный
    x: 2081,                       // координаты с пипетки
    y: 849,
    kind: "city",                  // тип, см. список ниже
    name: "Серый брод",            // как показывается на карте
    summary: "Одна строка для списка.",
    tags: ["торговля", "опасно"],  // метки, по ним работает поиск
    hidden: true,                  // необязательно: видно только мастеру
    art: "/images/locations/seryy-brod.png",  // необязательно
    lore: `Длинное описание в markdown.`,
    gmNotes: `Заметки только для мастера.`,
  },
```

Обязательны только `id`, `x`, `y`, `kind`, `name`, `summary`, `tags`, `lore`.
Строки `hidden`, `art` и `gmNotes` можно просто не писать.

### Типы локаций (`kind`)

| Значение   | Что показывает    | Цвет пина     |
|------------|-------------------|---------------|
| `capital`  | Столицы           | золотой       |
| `city`     | Города            | оранжевый     |
| `citadel`  | Цитадели гильдий  | фиолетовый    |
| `mountain` | Горы              | серый         |
| `forest`   | Леса              | зелёный       |
| `cursed`   | Проклятые земли   | красный       |
| `wild`     | Дикие земли       | болотный      |

Если нужен новый тип — добавь его в `LocationKind` и в `KIND_META` в том же
файле. Глиф бери из существующих: `crown`, `town`, `tower`, `peak`, `tree`,
`skull`, `wild` (они описаны в `src/web/lib/pins.ts`).

## 3. Как писать лор

Поле `lore` — обычный markdown внутри обратных кавычек `` ` ``. Работает:

```
Обычный абзац. Пустая строка = новый абзац.

**Жирным** — подзаголовок внутри абзаца.
*Курсивом* — цитаты и названия.

- список
- ещё пункт
```

Структура, которой держатся текущие 10 локаций (можно не соблюдать, но
единообразие выглядит опрятнее):

1. Первый абзац — как место выглядит.
2. **Чем известно.** — детали, за которые цепляются игроки.
3. **Кто правит.** — власть формальная и настоящая.
4. **Настроение сейчас.** — что изменилось прямо перед приходом партии.

### Важно про кавычки

Внутри `lore` и `gmNotes` нельзя ставить символ `` ` `` — он закроет строку.
Обычные кавычки «ёлочки» и апострофы — можно.

## 4. Заметки мастера и скрытые локации

- `gmNotes` — блок, который видно только на адресе с `?gm=1`.
- `hidden: true` — локация вообще не появляется на карте и в списке у игроков.

**Предупреждение:** и то и другое лежит в JS-файле сайта. Игрок, который
откроет исходники страницы, сможет это найти. Защита от случайного клика,
а не от целенаправленного поиска. Если нужны по-настоящему закрытые заметки —
скажи, вынесу их в отдельный файл, который не будет попадать в публичную сборку.

---

## 5. Арты локаций

1. Положи картинку в `packages/web/public/images/locations/`.
2. Пропиши путь в поле `art`, начиная со слэша:
   `art: "/images/locations/seryy-brod.png"`.

Оптимальный размер — примерно 1536×1024, панель обрезает по ширине.
Если `art` не указан, вместо картинки рисуется глиф типа локации — выглядит
нормально, так что арты можно добавлять постепенно.

---

## 6. Проверить и выложить

Локально:

```bash
cd noskap-map
bun run dev
```

Откроется на `http://localhost:4200`. Файл сохраняется — страница обновляется
сама.

Если что-то сломал, `bun run build` покажет ошибку и строку. Самые частые:
забытая запятая между блоками локаций и незакрытая обратная кавычка в `lore`.

Выложить обновление на GitHub Pages:

```bash
./build-pages.sh
```

и залить содержимое `pages-dist` (подробности — в `GITHUB-PAGES.md`).

## 7. Что ещё можно править в том же файле

В начале `locations.ts` есть блок `MAP_META`:

```ts
export const MAP_META = {
  width: 4146,      // размер исходной карты, не трогать
  height: 2354,
  tileSize: 256,
  maxZoom: 5,
  pixelsPerLeague: 24,   // масштаб для линейки
};
```

`pixelsPerLeague` — сколько пикселей карты составляют одну лигу. Значение 24
взято на глаз. Откалибруй так: измерь линейкой отрезок, для которого знаешь
реальное расстояние, и подгоняй число прямо в тулбаре линейки, пока цифры не
сойдутся. Устроившее значение впиши сюда, чтобы оно стало значением по
умолчанию.

Скорости путешествия правятся в `src/web/components/toolbar.tsx`, массив
`TRAVEL_MODES` (сейчас: пешком 8, верхом 16, форсированный марш 24 лиги в день).
